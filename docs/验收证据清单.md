# 验收证据清单

构建成功、设备实际运行和真实网络通信分别记录。出现 `NetworkReady` 不等于端到端数据流量已验证。
当前工作区没有 `tests/` 和 `test_apps/`，旧文档中的用例数量只代表历史记录，不能作为当前可执行测试入口。

- [移植设计](easytier-esp-port-design.md)：协议依据、架构与实现范围。

## 无硬件检查

激活 ESP-IDF 6.1 环境后，从仓库根目录构建主固件，检查命令实际退出码：

```bash
idf.py build
```

可选栈用量分析：

```bash
idf.py -DEASYTIER_STACK_USAGE=ON build
python3 tools/check_stack_usage.py
```

栈分析依赖编译器输出与调用图，只能作为近似参考；实际栈余量、调度和稳定性需上板核对。

## 硬件检查（仅由用户手动执行）

具体烧录、监控命令见[硬件联调指南](硬件联调指南.md)。代理不自行接触串口或烧录。

| 验收项 | 判定依据 |
| --- | --- |
| TCP/握手 | 同网络节点握手成功；断网、恢复后能重新连接 |
| RPC/保活 | 持续运行时能同步与保活，无异常重启、看门狗超时或重复断连 |
| 路由 | Linux 侧学到 ESP 地址，下一跳正确；断链后相关路径撤销或重新收敛 |
| 网卡/数据面 | 虚拟网卡地址与状态一致；直连及经中继的双向 ICMP/TCP/UDP 实际可达 |

日志需保留固件 ELF SHA256；flashed/built checksum 不匹配时，不据错配 ELF 的行号分析崩溃。

## 维护工具

`tools/` 仅保留：

- [check_stack_usage.py](../tools/check_stack_usage.py)：从构建产物分析任务栈用量。
- [vendor_tomlc17.sh](../tools/vendor_tomlc17.sh)：从固定提交导入 tomlc17 并重命名符号。

导入脚本会覆盖第三方源码，仅在明确更新依赖时执行，日常编译不需要运行。
